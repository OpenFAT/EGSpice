# Xyce 7.10 device-evaluation research

This audit identifies optimization candidates, not a proven explanation of the timing results. The parent investigation found substantially different saved-point counts: ESPice/Xyce were 1014/129 for ring, 532/139 for chain1k, 270/69 for chain10k, and 775/708 for logic. Those are preliminary output counts, not a substitute for accepted/rejected step and Newton-iteration counters. Match explicit maximum steps and compare waveform error before attributing the three Xyce wins to model or matrix code.

No simulator source was changed and no build or simulation was run for this audit. Xyce was inspected at official Release-7.10.0 commit `a592a42ae7472151d1c8e3bca0ca62d27476f2f3`, checked out in `/tmp/xyce-7.10-research`. ESPice was compared with benchmark baseline `ec53a724d1e67adcb54927e46fbd13af40aed1eb` in `/tmp/espice-bench-ec53a724`. Current `Circuit.zig` and `models/bsim4va.va` are byte-identical to that baseline; the current evaluator diff is confined to LTRA AC integration and its test import.

## Ranked experiments after matching transient work

1. **Measure the existing BSIM4 reduced-derivative seam first if device evaluation dominates.** `canNarrow` explicitly refuses `n_u > 8`, with a comment naming BSIM4 as intentionally unpriced. The generated BSIM4 examined here has 18 local unknowns but only 11 derivative-read nodes; maximal topological collapse reduces these to four distinct derivative lanes. Its four limiter-written nodes also map to four distinct roots, satisfying the existing limiter non-aliasing criterion. The postlayout cards leave RDSMOD/RGATEMOD/RBODYMOD/TNOIMOD at zero, whose VA branches select the maximal collapse. This makes a BSIM4-specific guarded experiment plausible; it does not establish a speedup. Preserve the wide path for other topology settings. Validate tied ports, polarity, limiting, all gate/body/resistance modes, F/Q/Jacobians, DC/AC/noise and transient waveforms before adoption. [eval.zig:726–752](https://github.com/OmarSiwy/ESPice/blob/ec53a724d1e67adcb54927e46fbd13af40aed1eb/src/device/eval.zig#L726), [model defaults:577–588](https://github.com/OmarSiwy/ESPice/blob/ec53a724d1e67adcb54927e46fbd13af40aed1eb/models/bsim4va.va#L577), [topology branches:9526–9582](https://github.com/OmarSiwy/ESPice/blob/ec53a724d1e67adcb54927e46fbd13af40aed1eb/models/bsim4va.va#L9526).

2. **Ablate Xyce's extra linear loading cache before implementing an ESPice equivalent.** Add `.OPTIONS DEVICE SEPARATELOAD=0` to an otherwise identical, explicit-max-step deck and inspect both elapsed time and step/Newton counts. This measures that feature's net effect in Xyce; its speedup is not directly transferable to ESPice. If passive loading is material, prototype an aggregate exact-linear R/C residual/charge path using ESPice's existing baseline and invalidation lifecycle. Keep affine/time-varying source terms, history, requested device currents, charge-site LTE data and model callbacks correct. A constant Jacobian alone does not prove all those effects can be skipped. Test passive-only, source-driven and mixed nonlinear decks, parameter/temperature changes and rejected steps.

3. **Only then consider stamp-address and model-code specialization microbenchmarks.** Compare instruction count, cache misses and assembly cost for existing u32 slot tapes versus pointer tapes; the latter use more address storage and complicate movable/shared planes. A dedicated handwritten BSIM4 rewrite is much higher risk than testing the existing four-lane route. Both simulators already cache parameter preprocessing and avoid sparse-position lookup in the hot stamp.

These priorities are conditional on profiles: if linear factorization dominates, defer to the independent solver/BTF investigation; if differences disappear under matched step limits, report timestep policy as the measured explanation and retain these as future optimization experiments.

## Claims this evidence does not support

- **“Xyce wins because it bypasses BSIM4 evaluation near convergence.”** The audited `Master::updateState` calls `updateIntermediateVars` for every BSIM4 instance. The 4.8.2 implementation's bypass mentions are comments about unused SPICE storage, not a demonstrated bypass path. Global modified-Newton/Jacobian-reuse policy requires separate analysis. [B4.C:10540–10549](https://github.com/Xyce/Xyce/blob/a592a42ae7472151d1c8e3bca0ca62d27476f2f3/src/DeviceModelPKG/OpenModels/N_DEV_MOSFET_B4.C#L10540), [B4p82.C:6748–6760,6999–7007](https://github.com/Xyce/Xyce/blob/a592a42ae7472151d1c8e3bca0ca62d27476f2f3/src/DeviceModelPKG/OpenModels/N_DEV_MOSFET_B4p82.C#L6748).
- **“Add analytic derivatives, constant-Jacobian caching, fused F/Q, or setup caching to ESPice.”** Those are already present. Accepted-point charge/state work also has a fused `acceptQ` path, so a generic “avoid evaluating charge twice” proposal is incomplete. [eval.zig:949–975,1669–1672](https://github.com/OmarSiwy/ESPice/blob/ec53a724d1e67adcb54927e46fbd13af40aed1eb/src/device/eval.zig#L949).
- **“The benchmark uses the identical BSIM4 implementation.”** Xyce defaults to 4.8.2 and dispatches versions at or above 4.80 to its 4.8.2 evaluator. ESPice's VA identifies itself as based on 4.8, and the benchmark generator does not specify VERSION. This is a model/accuracy control, not proof of a discrepancy or its performance cost. [B4.C:4834,4930–4965](https://github.com/Xyce/Xyce/blob/a592a42ae7472151d1c8e3bca0ca62d27476f2f3/src/DeviceModelPKG/OpenModels/N_DEV_MOSFET_B4.C#L4834), [ESPice VA:1–29,594](https://github.com/OmarSiwy/ESPice/blob/ec53a724d1e67adcb54927e46fbd13af40aed1eb/models/bsim4va.va#L1), [generator:30–32](https://github.com/OmarSiwy/ESPice/blob/ec53a724d1e67adcb54927e46fbd13af40aed1eb/tests/benchmark/postlayout/gen.py#L30).
